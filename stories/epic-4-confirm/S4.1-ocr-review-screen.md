# S4.1: Mobile — OCR Review & Confirm Screen

**Epic:** 4 — Confirmation & Expense History
**Depends-on:** S0.1, S0.2, S2.4, S3.7
**Priority:** HIGH
**Estimate:** L

## Context
The OCR review screen is where users verify and correct extracted receipt data before saving. Each item displays its confidence tier (HIGH/MEDIUM/LOW) with visual indicators. Users can edit any field, add missing items, or delete incorrect ones. This is the critical "gate" that ensures only user-verified data enters the Comparison Pool.

## Scope
- Editable header fields: retailer name, outlet, date (date picker), total (auto-updating)
- Items list with confidence-tier color indicators: green bar (HIGH, auto-confirmed), amber bar (MEDIUM, needs review), red bar (LOW, must fill manually)
- MEDIUM confidence items: shown with a picker of top-3 candidate matches for user selection
- LOW confidence items: raw OCR text highlighted, must be manually edited
- "Add Missing Item" button: appends blank row for manual entry
- Swipe left to delete item
- "Confirm All" button (sticky at bottom): validates all items have name + price, calls confirm API
- Loading spinner during confirm; inline error on failure
- Partial results warning banner: shown when OCR returned errors, highlights gaps
- On success: navigates to Home with success toast, expense list refreshes
- **Out of scope:** Bill splitting, price breakdowns, receipt image retention

## Acceptance Criteria
1. All OCR items displayed in scrollable list with confidence indicators
2. HIGH items green, auto-confirmed but editable; MEDIUM items amber with candidate picker; LOW items red, must be manually filled
3. User can edit retailer, date, any item field
4. User can add new items and delete existing items
5. "Confirm All" validates fields, calls confirm API, navigates to Home on success
6. Partial results banner when OCR returned errors
7. Total auto-updates as items are edited
8. Validation: all items must have name and positive unit_price
