# S4.3: Backend — Confirm Bill Endpoint

**Epic:** 4 — Confirmation & Expense History
**Depends-on:** S1.6, S3.7, S0.7
**Priority:** HIGH
**Estimate:** L

## Context
`POST /bills/confirm` is the most important write endpoint. It: (1) saves the confirmed bill and items to the Personal Bills DB, (2) writes anonymised item prices to the Comparison Pool DB (if user has community consent), and (3) deletes the temp S3 image. A single atomic operation from the mobile's perspective.

## Scope
- Accepts: objectKey, retailer (chain + outlet), date, items array (each with raw text, matched product, confidence, qty, unit, price), subtotal, gst, total
- Creates/finds retailer in Personal Bills DB
- Creates bill record + bill items linked to user
- Writes to Comparison Pool: for each confirmed item (HIGH or user-confirmed MEDIUM), UPSERT into prices table — increment receipt_count if matching price exists, otherwise insert new row
- Comparison pool entries contain NO user_id, bill_id, or full date — only item, price, unit, chain, outlet, month/year, source
- observed_month stored as YYYY-MM format only
- Deletes temp S3 image on success (fire-and-forget — don't fail the request if delete fails)
- Verifies S3 object no longer exists after confirm (for QA)
- Increments monthly scan quota counter (fires S7.2 if implemented; graceful no-op if not)
- LOW confidence items and items from users without community consent are NOT contributed to pool
- **Out of scope:** Transaction rollback across both DBs (pool write is best-effort)

## Acceptance Criteria
1. Bill + items created in Personal Bills DB with all fields
2. Retailer created or found by chain + outlet
3. Confirmed items flow to Comparison Pool as anonymised price entries
4. Duplicate prices (same product + chain + month + price) increment receipt_count
5. Comparison pool contains zero columns linking back to user or bill
6. observed_month is YYYY-MM format only — no full date, no user identifier
7. LOW tier items NOT contributed to pool
8. S3 image deleted after successful confirm; ObjectExists returns false
9. Outlet address stored but not user-identifiable
10. User without community consent → pool write skipped
11. Empty items list → 400 validation error

## Definition of Done
- [ ] POST /bills/confirm with full bill creation flow
- [ ] Personal Bills DB: bill + items saved
- [ ] Comparison Pool DB: anonymised prices contributed
- [ ] Anonymisation verified: zero user_id, bill_id, or full date in prices table
- [ ] S3 image deletion verified
- [ ] LOW tier exclusion verified
- [ ] Consent gate enforced
- [ ] Quota counter call (stub ok until S7.2)
- [ ] Ready for S4.4 (CRUD)
