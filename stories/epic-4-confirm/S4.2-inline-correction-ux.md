# S4.2: Mobile — Inline Correction UX

**Epic:** 4 — Confirmation & Expense History
**Depends-on:** S4.1
**Priority:** MEDIUM

## Context
Enhance the editability of the OCR review screen with polished UX: tap-to-edit any field, autocomplete product search from the catalogue, unit picker, numeric keypads, and undo on delete. These refinements reduce the friction of correcting OCR errors, increasing confirmation rates and data quality.

## Scope
- Tap-to-edit inline: tapping any item field switches to editable mode (text input, numeric keypad, or picker)
- Product autocomplete: typing in item name searches the product catalogue (debounced 300ms), shows dropdown of matches; selecting one auto-fills name, product ID, and unit
- `GET /products/search` backend endpoint for autocomplete (ILIKE matching, limited to 10 results)
- Unit picker: modal/bottom-sheet with predefined units (g, kg, ml, L, pc, pack, etc.) plus custom text option
- Numeric keyboard for price and quantity fields (decimal-pad, numeric)
- Swipe-to-delete with undo: swipe left → item removed → snackbar with "Undo" button (5s auto-dismiss)
- "Mark as new product" option when autocomplete has no match — saved without product ID
- Edits persist within the session (in scanStore memory)
- **Out of scope:** Edit history across app restarts, bulk actions on items

## Acceptance Criteria
1. Tap item name → inline text input opens with keyboard
2. Typing in name triggers autocomplete search with dropdown
3. Selecting from autocomplete fills name + unit
4. Unit picker opens on tap, shows predefined options + custom
5. Numeric keypad for price (decimal) and qty (integer)
6. Swipe left deletes item; undo snackbar restores it
7. Edits persist when navigating between fields
8. Unmatched items can be marked as "new product"

## Definition of Done
- [ ] Tap-to-edit inline for all item fields
- [ ] Autocomplete search endpoint + mobile integration
- [ ] Unit picker with predefined options
- [ ] Swipe-to-delete with undo
- [ ] "New product" marker for unmatched items
- [ ] Edits persist in scanStore during session
- [ ] Ready for S4.3 (confirm backend)
