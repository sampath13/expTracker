# S4.5: WatermelonDB Sync Adapter

**Epic:** 4 — Confirmation & Expense History
**Depends-on:** S0.3, S4.4
**Priority:** HIGH

## Context
Implement the sync adapter that keeps the local WatermelonDB cache in sync with the cloud Personal Bills DB. The app is offline-first — bills are readable without network via the local cache. Writes go through the API directly (optimistic). The adapter pulls bill summaries on launch and on foreground, and fetches full bill details on-demand.

## Scope
- `syncManager` module: fullSync (pull all bills into WatermelonDB), incrementalSync (pull changes since last sync — full sync for MVP), syncBillDetail (pull items for one bill on-demand), deleteLocalBill
- `useSync` hook: triggers fullSync on auth + app foreground; skips when offline (polls network state via NetInfo)
- Full sync uses cursor-based pagination to pull all bills; inserts into WatermelonDB only if not already present (UPSERT by ID)
- Bill detail sync: fetches items from API, replaces local items for that bill (simpler than diffing)
- Push pending: stub for future offline create flow (MVP: all writes go through API)
- Sync errors handled with retry (3 attempts with backoff), then skip — cached data remains available
- WatermelonDB query helper: `getBillsFromCache()` for the expense list screen
- **Out of scope:** Real-time sync via push notifications, conflict resolution UI, offline write queuing

## Acceptance Criteria
1. App launch (authenticated): bills synced from cloud to WatermelonDB
2. Cached bills readable without network
3. New bill (after confirm) appears in cache via refresh
4. Bill detail fetched on-demand when user taps a bill
5. Network error → sync skipped, cached data shown (no crash)
6. Multiple syncs don't duplicate records (UPSERT by ID)
