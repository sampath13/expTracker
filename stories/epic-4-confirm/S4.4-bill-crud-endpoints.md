# S4.4: Backend — Bill CRUD Endpoints

**Epic:** 4 — Confirmation & Expense History
**Depends-on:** S0.7, S1.6, S4.3
**Priority:** HIGH

## Context
Create the read and delete endpoints for bills. The mobile app uses these for the expense list (paginated) and bill detail views. Delete is a soft-delete — the bill is hidden from the user but preserved for audit; its comparison pool contributions are removed. Also exposes a product catalogue endpoint for the OCR service.

## Scope
- `GET /bills` — paginated bill list (cursor-based, newest first, 20 per page, optional date filters, excludes soft-deleted)
- `GET /bills/{id}` — full bill detail with all items and retailer info (404 for other users' bills or deleted bills)
- `DELETE /bills/{id}` — soft-delete bill (IsDeleted = true), remove contributions from comparison pool
- `GET /products/catalogue` — all products grouped by category (used by OCR service for fuzzy matching)
- `GET /products/search?q={query}` — search products by name for autocomplete (ILIKE, limit 10)
- Cursor-based pagination using bill ID for stable pagination across data changes
- **Out of scope:** Bill editing (update), hard delete, bulk delete

## Acceptance Criteria
1. GET /bills returns paginated list, newest first, with hasMore and nextCursor
2. Cursor pagination works correctly when items added between pages
3. Date filtering narrows results (fromDate/toDate)
4. GET /bills/{id} returns complete bill + items + retailer
5. Non-existent or other user's bill → 404
6. DELETE soft-deletes bill and removes pool contributions
7. GET /bills excludes soft-deleted bills
8. GET /products/catalogue returns products grouped by category
9. GET /products/search returns matching products for autocomplete

## Definition of Done
- [ ] GET /bills with cursor pagination + date filters
- [ ] GET /bills/{id} with full detail
- [ ] DELETE /bills/{id} with soft-delete + pool cleanup
- [ ] GET /products/catalogue for OCR service
