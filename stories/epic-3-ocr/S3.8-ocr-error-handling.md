# S3.8: OCR Error Handling & Partial Results

**Epic:** 3 — OCR Pipeline
**Depends-on:** S3.7
**Priority:** MEDIUM

## Context
OCR is imperfect — receipts produce partial results, garbled text, or nothing at all. Define a consistent error response contract that all OCR failure modes follow. Ensure users never see a cryptic crash; they always have a path forward (retry or manual entry). This story touches the Python service, .NET backend, and mobile UI.

## Scope
- Standardized error response contract: error code, human-readable message, machine-readable details, partial results (if any), canRetry flag, canManualEntry flag
- Error codes defined: IMAGE_LOAD_FAILED, IMAGE_TOO_SMALL, NO_TEXT_DETECTED, PARTIAL_PARSE, OCR_TIMEOUT, OCR_UNAVAILABLE, INTERNAL_ERROR
- Python service: all error paths return structured responses; async timeout at 10s
- .NET OcrServiceClient: handles all HTTP status codes, deserializes error responses, passes error info to mobile
- POST /bills/scan updated to include error status and partial results when OCR returns errors
- Mobile: UploadProgressScreen error states — appropriate UI for each error code (retry button vs manual entry link vs both)
- Partial results: items that parsed successfully are shown on review screen; failed items highlighted for manual input
- All OCR errors logged with structured fields for monitoring
- **Out of scope:** Error analytics dashboard, automated OCR quality monitoring

## Acceptance Criteria
1. Corrupt image → 400 IMAGE_LOAD_FAILED; "Try Again" and "Enter Manually" shown
2. Too-small image → 400 IMAGE_TOO_SMALL; "Retake" prompt
3. No text detected → 422 NO_TEXT_DETECTED
4. Partial parsing → 200 with `partial: true`; parsed items shown, gaps highlighted
5. OCR timeout (10s) → 408 with retry option
6. OCR service down → 503 with retry option
7. All error responses follow the defined contract
8. Mobile handles each error with appropriate UI actions
9. No uncaught exceptions surface as crashes

## Definition of Done
- [ ] Error contract defined across all three tiers
- [ ] Python: all error paths return structured responses
- [ ] Python: async timeout at 10s
- [ ] .NET: OcrServiceClient handles all error status codes
- [ ] .NET: POST /bills/scan returns error info + partial results
- [ ] Mobile: error state UI per error code
- [ ] Mobile: partial results warning on review screen
- [ ] Ready for production OCR error handling
