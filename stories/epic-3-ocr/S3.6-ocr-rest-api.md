# S3.6: OCR REST API Endpoints

**Epic:** 3 — OCR Pipeline
**Depends-on:** S3.5
**Priority:** HIGH

## Context
Expose the full OCR pipeline as a REST API. The .NET backend calls this service with an S3 object key; the OCR service downloads the receipt image, runs the full pipeline (preprocess → OCR → parse → match), and returns structured JSON. The service is stateless and independently scalable.

## Scope
- `POST /ocr/scan` endpoint: accepts S3 URL or base64 image, returns structured receipt data
- Downloads image from S3 (S3Ninja dev / AWS prod), processes, cleans up temp file
- Full pipeline integration: preprocessing → PaddleOCR → field parsing → category detection → product matching
- Response includes: retailer, date, items (with matched product ID, name, confidence tier), totals, processing stats
- MEDIUM confidence items include `candidate_matches` array for user review
- Processing stats: total time, text blocks detected, items parsed, confidence tier distribution
- Partial success: if some items parse but others fail, return what was extracted with error details
- Response time target: < 5s; .NET backend times out at 15s
- **Out of scope:** Batch processing, async processing, webhook notifications

## Acceptance Criteria
1. POST /ocr/scan with valid S3 URL returns structured receipt data
2. Items include matched_product_id, matched_name, confidence, confidence_tier
3. MEDIUM confidence items include candidate_matches
4. Processing time tracked in response stats
5. S3 image downloaded, processed, temp file deleted
6. Concurrent requests handled without state contamination
7. Invalid URL → 400; image with no text → 422

## Definition of Done
- [ ] POST /ocr/scan endpoint with S3 URL + base64 support
- [ ] S3 download → decode → process → cleanup flow
- [ ] Full pipeline integration
