# S3.5: RapidFuzz Product Matching

**Epic:** 3 — OCR Pipeline
**Depends-on:** S3.4, S0.7
**Priority:** HIGH

## Context
Match each receipt line item to a canonical product in the Comparison Pool using RapidFuzz fuzzy string matching. Matching is scoped to the item's assigned category to prevent cross-category false matches. Three confidence tiers determine the downstream behavior: auto-accept (HIGH), ask user (MEDIUM), treat as new product (LOW).

## Scope
- `match_item()`: fuzzy-matches an item name against candidate products in its category using RapidFuzz `token_set_ratio` (handles token reordering well for receipt text)
- Confidence tiers: HIGH (>85% match) → auto-accept; MEDIUM (60-85%) → return top-3 candidates for user confirmation; LOW (<60%) → no match, treat as new
- `ProductCatalogue` class: fetches products from .NET backend grouped by category, caches for 5 minutes
- Matching respects category boundaries (only match Dairy items against Dairy products); falls back to all categories if no candidates in assigned category
- Performance target: match 10 items against a 500-product pool in < 100ms
- **Out of scope:** ML-based product matching, user feedback loop for improving matches

## Acceptance Criteria
1. Exact match → 100% confidence, HIGH tier
2. Token-reordered name → >85% confidence, HIGH tier
3. Partially different name → 60-85% confidence, MEDIUM tier, top-3 candidates returned
4. Completely different product → <60% confidence, LOW tier
5. Category boundaries respected (Dairy item matched against Dairy candidates only)
6. No candidates in category → falls back to all categories
7. 10 items × 500 products completes in < 100ms
8. Product catalogue cached with 5-min TTL

## Definition of Done
- [ ] match_item with three-tier confidence
- [ ] ProductCatalogue with fetch + cache
- [ ] MEDIUM tier returns top-3 candidates
- [ ] Category-scoped matching with all-category fallback
- [ ] Integrated into OCR pipeline
- [ ] Performance: < 100ms for typical receipt
- [ ] Ready for S3.6 (OCR REST API)
