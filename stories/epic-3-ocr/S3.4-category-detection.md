# S3.4: Category Detection via Keyword Prefix Filter

**Epic:** 3 — OCR Pipeline
**Depends-on:** S3.3
**Priority:** HIGH

## Context
Assign a product category to each receipt line item using a keyword prefix lookup map. Categories narrow the candidate set for RapidFuzz matching (S3.5), improving both speed and accuracy by preventing cross-category false matches (e.g., matching "YOGURT" against "YOGURT-FLAVORED CANDY").

## Scope
- `categories.json` file with 10 categories and their keyword prefixes (Dairy: MILK, YOGURT, CHEESE...; Bakery: BREAD, BUN, CAKE...; Staples: RICE, FLOUR, OIL...; etc.)
- Category detection function: tokenize item name, match first 1-3 tokens against keyword prefixes (case-insensitive, longest prefix match first)
- Also check if item name starts with any keyword (for multi-word keywords like "ICE CREAM")
- Add `category` field to each item in the parse result
- Log category distribution per receipt
- Categories file is editable without code changes
- Singapore-grocery-specific keywords included (ATTA, DAL, LENTIL for Indian provision shops)
- **Out of scope:** Embedding-based category detection, ML classification

## Acceptance Criteria
1. "MILK FULL CREAM 1L" → Dairy
2. "SUNSHINE WHITE BREAD 600G" → Bakery
3. "CHICKEN THIGH BONELESS" → Meat/Seafood
4. "COCA COLA ZERO 1.5L" → Beverages
5. "RICE BASMATI 5KG" → Staples
6. Unknown items → "Uncategorised"
7. Multi-word prefixes work: "ICE CREAM" → Frozen
8. categories.json loaded once at startup
9. Tests cover 20+ examples across all categories

## Definition of Done
- [ ] categories.json with 10 categories and keyword lists
- [ ] Category detection function with prefix + start-of-string matching
- [ ] Multi-word prefix support
- [ ] Integrated into parse pipeline
