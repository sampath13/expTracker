# S3.7: Backend — OCR Orchestration Endpoint

**Epic:** 3 — OCR Pipeline
**Depends-on:** S0.6, S1.6, S3.6
**Priority:** HIGH

## Context
The .NET backend's `POST /bills/scan` endpoint orchestrates the OCR flow. It receives the S3 object key from the mobile app, verifies the image exists, calls the Python OCR service, and returns structured line items to the mobile app for review. This is the bridge between mobile and OCR.

## Scope
- `OcrServiceClient`: typed HttpClient wrapper for calling the Python OCR service
- `POST /bills/scan` endpoint: accepts objectKey, verifies object exists in S3, calls OCR service, returns results
- Response includes: retailer, date, items with confidence tiers, totals, processing stats
- DTOs matching the Python OCR service response contract
- Error handling: image not found (400), OCR service down (503), OCR processing failure (502), no text detected (422)
- OCR service health check integrated into the main health check endpoint
- Timeout: 15s via HttpClient configuration; logs all OCR calls with object key
- **Out of scope:** Retry logic, OCR result caching

## Acceptance Criteria
1. POST /bills/scan with valid objectKey → structured OCR results
2. Response includes items with confidence tiers and candidate_matches for MEDIUM items
3. S3 object not found → 400 IMAGE_NOT_FOUND
4. OCR service down → 503 OCR_UNAVAILABLE
5. OCR processing failure → 502 OCR_SERVICE_ERROR
6. No text detected → 422 NO_TEXT_DETECTED
7. Unauthenticated → 401
8. Logs captured for all requests and failures
