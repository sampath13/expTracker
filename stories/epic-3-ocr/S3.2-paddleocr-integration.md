# S3.2: PaddleOCR Integration

**Epic:** 3 — OCR Pipeline
**Depends-on:** S3.1
**Priority:** HIGH

## Context
Wire preprocessed images into PaddleOCR for text detection and recognition. PaddleOCR handles both English and Chinese text natively — critical for Singapore receipts which often mix languages. The output is raw text blocks with bounding boxes and confidence scores. No receipt field parsing yet — just text detection.

## Scope
- PaddleOCR English model loaded at service startup (singleton in app state)
- PaddleOCR Chinese model loaded if available (graceful fallback to English-only)
- `run_ocr()` function: accepts preprocessed image, returns list of text blocks
- Each block: text, confidence score, bounding box coordinates, detected language, block dimensions
- Results sorted top-to-bottom, left-to-right (receipt reading order)
- Deduplication: if both English and Chinese models detect overlapping blocks, keep the one with higher confidence
- Updated `POST /ocr/test` endpoint: runs preprocessing + OCR, returns text blocks
- Performance target: < 3s for a standard receipt
- **Out of scope:** Handwriting recognition, vertical text, very large receipts (> A4)

## Acceptance Criteria
1. English receipt: all text blocks detected with `language: 'en'`
2. Chinese receipt: Chinese characters detected and returned
3. Results sorted top-to-bottom, left-to-right
4. Each result has text, confidence, bbox, language, block dimensions
5. Blank image returns empty list (no crash)
6. OCR completes in < 3 seconds for standard receipt
7. Model loaded once at startup, not per request

## Definition of Done
- [ ] `run_ocr()` function with both language models
- [ ] English model loaded at startup
- [ ] Chinese model with graceful fallback
- [ ] Results sorted in reading order
- [ ] Deduplication for overlapping blocks
- [ ] Updated test endpoint
- [ ] Performance: < 3s
- [ ] Ready for S3.3 (receipt field parsing)
