# S5.6: Comparison Framing Text Policy

**Epic:** 5 — Comparison Engine
**Depends-on:** S5.2
**Priority:** HIGH

## Context
Codify and enforce the neutral communication policy across all comparison surfaces. Per thread T14, the app must never label a retailer as "expensive" — only factual statements like "available for less at X." This story ensures the backend enforces this in API responses and the mobile app only displays backend-provided text (no hardcoded judgment words).

## Scope
- Backend: all comparison response text uses only allowed phrasing — "available for less at [Chain]", "lower price found at [Chain]", "price difference: $X"
- Backend: trust indicators included on every response — "Based on N receipts" and "Last reported X days ago"
- Backend: prohibited words filtered or flagged in code review — "expensive", "overpriced", "ripoff", "avoid", "bad value"
- Mobile: all comparison text sourced from backend responses only — no hardcoded judgment words in UI
- Mobile: color indicators always accompanied by text labels (not color-only — accessibility)
- Code review checklist item added: no prohibited framing words in any comparison-related code
- **Out of scope:** Automated scanning for prohibited words in CI (future enhancement)

## Acceptance Criteria
1. All comparison API responses use neutral "available for less at" phrasing
2. No comparison response contains "expensive", "overpriced", "ripoff", "avoid", "bad value"
3. Every comparison includes trust indicators (receipt count + last observed)
4. Mobile UI displays only backend-provided text for comparison results
5. Color dots have text label counterparts

## Definition of Done
- [ ] Backend response templates use only allowed phrasing
- [ ] Trust indicators on every comparison endpoint response
- [ ] Mobile UI text sourced from API (no hardcoded judgment)
- [ ] Accessibility: text labels alongside color indicators
- [ ] Code review checklist updated
- [ ] Ready for all comparison user-facing features
