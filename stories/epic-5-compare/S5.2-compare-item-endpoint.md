# S5.2: Backend — Item Comparison Endpoint

**Epic:** 5 — Comparison Engine
**Depends-on:** S5.1, S1.6
**Priority:** HIGH

## Context
Expose the comparison engine via a REST endpoint. The mobile app calls this for each item in a bill detail and for the dedicated Compare tab. The response includes the color tier, all chain prices, savings amount, and trust indicators. Responses are cached since prices change slowly.

## Scope
- `GET /compare/item?product_id={id}&user_price={price}&user_chain={chain}&unit={unit}` — returns ItemComparisonResult with tier, color, min price, min chain, savings, all chain prices, receipt count, last observed
- Response includes trust metadata: "Based on N receipts, last reported X days ago"
- Neutral framing in all response text: "available for less at [Chain]" (never "expensive")
- Cached with 1-hour TTL (in-memory or Redis stub) — prices don't change rapidly
- Outlet-level data returned when available (for future display; MVP uses it internally)
- **Out of scope:** Historical price charts, price alerts

## Acceptance Criteria
1. GET /compare/item with valid product returns tier + chain prices
2. Response includes: tier, color, minPrice, minChain, savingsAmount, allChainPrices, receiptCount, lastObserved
3. No data → "no_data" tier, empty chain prices (not an error)
4. All text uses neutral framing (no "expensive" anywhere)
5. Cached responses served for subsequent identical requests within TTL
6. Unauthenticated → 401
