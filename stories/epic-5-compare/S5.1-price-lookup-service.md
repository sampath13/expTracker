# S5.1: Backend — Price Lookup Service

**Epic:** 5 — Comparison Engine
**Depends-on:** S0.7, S6.3
**Priority:** HIGH

## Context
Build the core price comparison logic. Given a product ID and the user's purchase price, find the best available price across all retailer chains in the last 30 days (60-day fallback). Calculate the percentage difference and assign a color tier (green/grey/amber/red). This is the engine behind every comparison displayed to users.

## Scope
- `PriceComparisonService`: CompareItemAsync (single item) and CompareBasketAsync (batch of items)
- 30-day primary price window; extends to 60 days as fallback (flag indicates older data)
- Minimum price across all chains is the benchmark
- Color tier assignment: green ≤5%, grey 5-15%, amber 15-30%, red >30% above lowest
- If user's own chain is the cheapest → always green (good deal)
- All chains' prices returned sorted cheapest first with receipt counts and last-observed dates
- Basket comparison aggregates per-item results and identifies best overall chain
- No-data state returned when no comparison data exists (not an error)
- **Out of scope:** Price prediction, outlet-level comparison display (data collected but not compared)

## Acceptance Criteria
1. Item with recent data returns tier + color + chain prices
2. Correct thresholds: ≤5% green, 5-15% grey, 15-30% amber, >30% red
3. "no_data" tier when no comparison data available
4. 30-day primary / 60-day fallback window
5. All chain prices sorted cheapest first
6. ReceiptCount and LastObserved populated
7. User's chain = cheapest → always green
