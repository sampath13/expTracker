# S5.5: Mobile — Bill Detail Comparison Integration

**Epic:** 5 — Comparison Engine
**Depends-on:** S4.7, S5.2
**Priority:** HIGH

## Context
Enhance the bill detail screen (S4.7) to fetch and display comparison data lazily. When a user opens a bill, comparison data is fetched for each matched item and cached in component state. This ties the comparison engine output directly to the user's purchase history — the core value prop.

## Scope
- On bill detail load, for each item with a matched_product_id: fetch comparison from GET /compare/item
- Display color dot + text tier label per item row
- Expandable panel per item showing full comparison detail (prices, trust indicators)
- Trust line always visible: "Based on N receipts, last reported X days ago"
- No-match items: neutral state with "Scan more receipts to enable price comparison for this item"
- Comparison results cached in component state (re-fetched on each screen open — acceptable for MVP)
- Neutral framing enforced per architecture.md section 8.4

## Acceptance Criteria
1. Bill detail shows color dots for all matched items
2. Expanding an item shows comparison details with trust indicators
3. No-match items show neutral explanation
4. "Based on N receipts" visible on every comparison
5. All text uses neutral framing

## Definition of Done
- [ ] Comparison data fetched and displayed per matched item
- [ ] Color dots + text labels
- [ ] Expandable comparison panel
- [ ] Trust indicators on every comparison
- [ ] Neutral framing verified on all text
- [ ] Ready for user-facing comparison experience
