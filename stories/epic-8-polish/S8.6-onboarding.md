# S8.6: Mobile — First-Launch Onboarding

**Epic:** 8 — Settings, Profile & Polish
**Depends-on:** S0.1
**Priority:** LOW

## Context
Create a brief onboarding flow shown to new users on first launch. Three screens communicate the app's core value: scan receipts to track spending, discover where items cost less, and contribute data to help the community. The onboarding is skippable and shown only once (tracked via local flag).

## Scope
- Three onboarding screens with simple illustrations/icons and taglines:
  1. "Scan your grocery receipts" — camera/receipt illustration
  2. "Track your spending automatically" — expense list illustration
  3. "Find better prices across stores" — comparison illustration
- Swipe between screens; dot indicators at bottom
- "Skip" button on every screen (top-right)
- "Get Started" button on last screen → navigates to Register/Login
- Shown only on first app install (AsyncStorage flag `onboarding_complete`)
- **Out of scope:** Animated illustrations, personalized onboarding based on user type

## Acceptance Criteria
1. Onboarding shown on first launch after install
2. User reads about the app's 3 core features (scan, track, compare) before signing up
3. User can swipe between screens to read at their own pace
4. Dot indicators update to reflect current screen position
5. "Skip" button present on all screens — exits to auth immediately
6. "Get Started" on last screen navigates to Register/Login
7. Onboarding never shown again after user completes or skips it

## Definition of Done
- [ ] OnboardingScreen with 3-page swiper
- [ ] Dot indicators that track current page
- [ ] Skip button on all pages
- [ ] Get Started on last page
- [ ] Persistence: shown only once via AsyncStorage
- [ ] Ready for polished first-launch experience
