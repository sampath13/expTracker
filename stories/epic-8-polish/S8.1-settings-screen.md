# S8.1: Mobile — Settings & Profile Screen

**Epic:** 8 — Settings, Profile & Polish
**Depends-on:** S0.1, S0.2, S1.6, S1.7, S1.10
**Priority:** MEDIUM

## Context
Build the Settings tab and its associated backend endpoints. Shows account information (email, mobile, Google account link), user profile (creation date, current tier, subscription management), consent toggles, app version, privacy policy link, and sign-out button. This single story consolidates the former S8.1 (settings), S8.3 (profile), and S8.4 (profile endpoints) into one coherent deliverable — the profile screen is a natural section within settings, and the endpoints are <30 lines of wiring.

## Scope
### Settings Screen
- Sections: Account, Privacy, About
- Account section: email (read-only), mobile (editable inline), Google account linked indicator
- Profile section (within Account): display name, account creation date, tier badge ("Free" / "Premium" / "Founder"), "Manage Subscription" link → navigates to upsell (S7.4) for free users
- Privacy section: two consent toggles (community contribution, marketing opt-in) — wired to S1.7 endpoints
- About section: privacy policy link (in-app webview or external browser), terms of service link, app version + build number
- Danger zone: "Delete all my data" option (future scope — placeholder only)
- Sign-out button: clears tokens, resets auth state, navigates to login
- Confirmation dialog on sign-out

### Backend Profile Endpoints
- `GET /user/profile` — returns email, mobile, google_linked (bool), display_name, tier, created_at
- `PATCH /user/profile` — update mobile number; audit log the change
- Mobile number validation: Singapore format, unique (optional — allow duplicates for MVP)

- **Out of scope:** Full account deletion, push notification settings, theme/dark mode, profile photo, email/password change

## Acceptance Criteria
1. Settings screen shows account info, profile details, consent toggles, app version
2. Email displayed (read-only); tap to edit mobile number inline
3. Google account linked indicator shown when applicable
4. Profile section shows display name, creation date, tier badge
5. "Manage Subscription" navigates to upsell for free users; hidden for premium/founder
6. Both consent toggles functional — update on backend via S1.7
7. Privacy policy and terms links open correctly
8. Sign out clears session and returns to login with confirmation dialog
9. GET /user/profile returns user info for authenticated user
10. PATCH /user/profile updates mobile number with validation
11. Invalid mobile format returns validation error
12. Audit log created on mobile number change
13. Unauthenticated requests to profile endpoints return 401
