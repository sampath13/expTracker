# S8.2: Mobile — Consent Toggle Behavior

**Epic:** 8 — Settings, Profile & Polish
**Depends-on:** S8.1, S1.7
**Priority:** MEDIUM

## Context
Implement the consent toggle behavior in the Settings screen. When a user changes their community contribution consent, the backend is updated immediately and an audit record is created. Toggling off shows a confirmation dialog explaining that existing contributions remain but new ones won't be added.

## Scope
- Community contribution toggle: immediate backend update on change; optimistic UI (toggle updates instantly)
- Toggle OFF: confirmation dialog explaining "Your existing contributions will remain in the pool but no new data will be added. Continue?"
- Marketing opt-in toggle (future scope placeholder — non-functional or behind feature flag)
- Toggle state fetched from GET /user/consent on Settings screen mount
- Error handling: if backend update fails, revert toggle to previous state + show error
- Accessible: toggle has text label, not color-only (green/red toggles need text)
- **Out of scope:** Granular per-category consent, consent history display

## Acceptance Criteria
1. Toggle updates consent on backend immediately
2. Toggle OFF shows confirmation dialog before change
3. Toggle ON changes immediately without dialog
4. State synced from backend on screen mount
5. Backend failure reverts toggle to previous state

## Definition of Done
- [ ] Toggle wired to PATCH /user/consent
- [ ] OFF toggle shows confirmation dialog
- [ ] ON toggle immediate (no dialog)
- [ ] State fetched on mount
- [ ] Error recovery (revert on failure)
- [ ] Ready for PDPA-compliant consent management
