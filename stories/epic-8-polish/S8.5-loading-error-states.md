# S8.5: Mobile — Loading & Error State Sweep

**Epic:** 8 — Settings, Profile & Polish
**Depends-on:** S4.6, S5.4
**Priority:** HIGH

## Context
Audit every screen in the app and ensure all API-driven states are handled: loading (skeleton/spinner), error (with retry), empty (with guidance), and offline. No screen should show a blank white void or an unhandled crash. This is a quality sweep across all screens built in Epics 1-7.

## Scope
- Loading states: skeleton components for expense list, bill detail, comparison results; spinner for auth, upload, confirm
- Error states: inline error message + retry button for all API failures; network connectivity listener showing offline banner
- Empty states: "No bills yet", "No comparison data", "No search results" — each with appropriate illustration and action button
- Offline detection: banner at top when network is lost; cached data shown where available; actions requiring network disabled
- Screens covered: Login, Register, ExpenseList, BillDetail, Compare, OCR Review, UploadProgress, Home
- Consistent error styling: red banner for critical, amber for warnings, inline for field-level
- **Out of scope:** Custom illustrations for empty states (use simple icons/text for MVP), automated screenshot testing

## Acceptance Criteria
1. Every screen shows a loading indicator while fetching data (no blank screens)
2. Every screen shows an error state with retry on API failure
3. Every list screen shows an empty state with guidance when no data
4. Offline banner shown when network is lost
5. No unhandled exceptions cause blank/white screens
6. All loading/error/empty states use consistent styling

## Definition of Done
- [ ] Loading skeletons/spinners on all async screens
- [ ] Error + retry on all API failure paths
- [ ] Empty states with illustrations + CTAs on all list screens
- [ ] Network offline banner (NetInfo)
- [ ] Consistent styling across all state components
- [ ] Ready for production-quality UX
