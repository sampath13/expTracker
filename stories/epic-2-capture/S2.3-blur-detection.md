# S2.3: Mobile — On-device Blur Detection

**Epic:** 2 — Receipt Capture & Image Upload
**Depends-on:** S0.5
**Priority:** HIGH

## Context
Implement on-device image quality verification that runs immediately after photo capture. A computation of Laplacian variance on the captured image determines if it's sharp enough for OCR. Blurry images are flagged before upload, saving network bandwidth and avoiding failed OCR processing.

## Scope
- Native Android module `BlurDetector` that computes Laplacian variance from image bitmap
- Module downsamples image to 200×200 for speed, applies Laplacian kernel, computes variance
- JS bridge: `checkBlur(imagePath)` → returns variance value
- Threshold: variance < 100 → considered blurry (tune empirically with sample receipts)
- Integration into ScanReceiptScreen capture flow (S2.2)
- Performance target: < 200ms for the check
- If native module is too complex for MVP: skip, always proceed to upload, rely on OCR service partial results (acceptable MVP trade-off)
- **Out of scope:** Brightness detection, tilt detection, real-time frame processor blur detection

## Acceptance Criteria
1. Blur detection runs automatically after photo capture
2. Sharp image (variance > 100) → proceeds without prompt
3. Blurry image (variance < 100) → retake prompt shown
4. "Retake" returns to camera; "Use Anyway" proceeds despite blur
5. Detection takes < 200ms (not perceptible to user)
6. Native module registered and callable from JS

## Definition of Done
- [ ] BlurDetector native Android module implemented and registered
- [ ] checkBlur() utility returns variance
- [ ] Integrated into ScanReceiptScreen capture flow
- [ ] Retake prompt UI
- [ ] Performance: < 200ms
- [ ] Threshold documented and tunable
- [ ] Ready for S2.4 (upload flow)
