# S2.4: Mobile — Image Upload Flow

**Epic:** 2 — Receipt Capture & Image Upload
**Depends-on:** S0.2, S1.10, S2.1, S2.2
**Priority:** HIGH

## Context
Wire the full upload pipeline: after quality check passes, get a pre-signed URL from the backend, upload the image directly to S3/S3Ninja, then trigger OCR processing. The Zustand scan store tracks upload progress. The local image is deleted from the device after successful upload.

## Scope
- `imageService.js`: getUploadUrl(), uploadImage (PUT to S3 with progress tracking), triggerOcr(), deleteLocalImage()
- `UploadProgressScreen`: animated progress bar during upload, status text (uploading/processing)
- `scanStore` full implementation: captureImage, startUpload (orchestrates the full pipeline), clearScan, setOcrResult
- Upload progress relayed via `onProgress` callback (0% → 100%)
- On success: local image deleted, OCR triggered, result stored in scanStore, navigate to ConfirmOCR
- On error: error screen with retry and manual entry options
- Network timeout: 30s for upload, 15s for OCR trigger
- Cancel button during upload: abandons, returns to camera
- Multiple rapid captures blocked during upload
- **Out of scope:** Background upload, upload resumption after app kill

## Acceptance Criteria
1. Photo captured → upload starts automatically → progress bar shown
2. Upload progress updates smoothly 0% → 100%
3. Success: local image deleted, OCR triggered, result stored
4. Complete → navigates to OCR review screen
5. Network error → error screen with retry button
6. Cancel button abandons upload, returns to camera
7. Upload timeout (30s) → error with cancel option
8. Sequential captures during upload are blocked
