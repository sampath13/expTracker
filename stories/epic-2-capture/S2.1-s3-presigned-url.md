# S2.1: S3 Pre-signed URL Endpoint

**Epic:** 2 — Receipt Capture & Image Upload
**Depends-on:** S0.6, S0.7, S0.9, S1.6
**Priority:** HIGH

## Context
Create the backend endpoint that generates S3 pre-signed URLs for direct image upload from the mobile app. In development, it talks to S3Ninja (localhost:9444). In production, it talks to AWS S3 (ap-southeast-1). The .NET backend code is identical in both environments — only the endpoint URL changes via config.

## Scope
- `StorageService` with methods: generate upload URL (PUT, 5-min expiry), delete object, check object existence
- `GET /bills/upload-url` endpoint — returns pre-signed URL + objectKey (UUID) + expiry timestamp
- Object key format: `receipts/{guid}.jpg`
- S3 bucket (`receipt-images`) must exist in S3Ninja (created in S0.9)
- Bucket-level lifecycle policy for 2-hour TTL on unconfirmed uploads (simulated in dev)
- AWS SDK configured with S3Ninja endpoint in dev (`ServiceURL`, `ForcePathStyle = true`)
- **Out of scope:** Multi-part upload, image validation, direct upload from mobile (mobile story S2.4)

## Acceptance Criteria
1. GET /bills/upload-url returns pre-signed URL + objectKey + expiry
2. PUT to the pre-signed URL uploads a file to S3Ninja
3. File readable via S3 API after upload
4. Pre-signed URL expires after 5 minutes (verify by waiting)
5. Unauthenticated request returns 401
6. Works against S3Ninja — no AWS account needed

## Definition of Done

- [ ] Pre-signed PUT URL works against S3Ninja
- [ ] URL expiry enforced
