# S1.1: ASP.NET Identity Setup

**Epic:** 1 — Authentication & User Management
**Depends-on:** S0.6, S0.7
**Priority:** HIGH

## Context
Configure ASP.NET Core Identity with the custom User entity. Identity provides password hashing, user validation, and external login provider support. The User entity extends IdentityUser with custom fields for the app (mobile, Google ID, tier, consent flags, scan quotas).

## Scope
- Configure Identity services in `Program.cs` with relaxed password rules (min 8 chars, no special/digit/uppercase required)
- User entity inherits from `IdentityUser<Guid>`, adding: Mobile, GoogleId, Tier (free/premium/founder), CommunityContributionConsent, ScansThisMonth, ComparisonsThisMonth
- Identity tables mapped to lowercase names (users, roles, user_roles, etc.)
- `PersonalBillsDbContext` changed to inherit from `IdentityDbContext` instead of plain DbContext
- New migration for Identity tables (AspNetUsers, AspNetRoles, etc.)
- No email confirmation required for MVP
- **Out of scope:** Registration/login endpoints, Google auth, token issuance

## Acceptance Criteria
1. User entity has all custom fields alongside Identity base fields
2. Identity tables created with lowercase names
3. Migration generates Identity schema without errors
4. A user created via UserManager has password hashed (plain text never stored)
5. Password validation: correct password passes, wrong password fails
6. Email confirmation is NOT required

## Definition of Done
- [ ] Identity configured in Program.cs
- [ ] User entity extends IdentityUser<Guid> with custom properties
- [ ] Identity migration created and applied
- [ ] Integration test: create + validate user via UserManager
- [ ] Ready for S1.2, S1.3, S1.4
