# S1.7: Consent Storage & Audit Log

**Epic:** 1 — Authentication & User Management
**Depends-on:** S1.1
**Priority:** MEDIUM

## Context
Create endpoints for reading and updating user consent flags, with an immutable audit log of every change. Users can toggle their community contribution consent — this determines whether their confirmed bill data flows to the anonymised Comparison Pool. The audit trail satisfies PDPA compliance.

## Scope
- `GET /user/consent` — returns current consent state for authenticated user (community contribution, marketing opt-in)
- `PATCH /user/consent` — updates consent flags, creates audit record for each changed field
- `ConsentAudit` table: immutable, append-only — records field name, old value, new value, user ID, timestamp
- Changed-at timestamps on User entity for each consent field
- Serilog logging on consent changes
- **Out of scope:** Marketing opt-in enforcement (future), GDPR export

## Acceptance Criteria
1. GET /user/consent returns current consent state
2. PATCH /user/consent updates flags and creates audit record
3. Audit record contains old value, new value, timestamp — immutable
4. CommunityContributionConsent stored correctly from registration (S1.2)
5. Unauthenticated requests return 401

## Definition of Done
- [ ] GET and PATCH /user/consent endpoints
- [ ] ConsentAudit entity + table created via migration
- [ ] Changed-at timestamps on User entity
- [ ] Serilog logging on consent changes
- [ ] Ready for S6.5 (consent gate), S8.2 (settings toggle)
