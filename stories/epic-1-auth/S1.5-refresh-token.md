# S1.5: JWT Refresh Token Rotation

**Epic:** 1 — Authentication & User Management
**Depends-on:** S1.3
**Priority:** HIGH

## Context
Implement the refresh token rotation endpoint. When the JWT expires, the mobile app sends the refresh token. The backend validates it, revokes the old token (single-use), and issues a new pair (JWT + refresh token). If a revoked token is reused, it indicates possible token theft — all tokens for that user are revoked, forcing re-login.

## Scope
- `POST /auth/refresh` endpoint accepting refresh token string
- Validate: hash incoming token, find in DB, check not revoked, check not expired
- Rotation: revoke old token, issue new refresh token (SHA256 hash stored), issue new JWT
- Token reuse detection: if a revoked token is submitted, revoke ALL user tokens and log warning
- New refresh token has 30-day expiry from time of refresh
- **Out of scope:** Device fingerprinting for additional theft detection

## Acceptance Criteria
1. Valid refresh token → 200 with new JWT + new refresh token
2. Old refresh token is revoked in DB after use
3. Using the old (now-revoked) refresh token → 401
4. Using a non-existent token → 401
5. Using an expired token → 401
6. New refresh token has 30-day expiry from refresh time
7. Multiple consecutive refreshes work (each rotates)
