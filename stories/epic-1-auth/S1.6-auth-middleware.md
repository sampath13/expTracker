# S1.6: Auth Middleware & [Authorize] Protection

**Epic:** 1 — Authentication & User Management
**Depends-on:** S1.3
**Priority:** HIGH

## Context
Wire JWT authentication into the ASP.NET middleware pipeline. Create helper methods to extract the current user's ID, email, and tier from JWT claims. Add a protected test endpoint to verify auth works. Every subsequent API endpoint uses `[Authorize]` and the user context helpers.

## Scope
- Verify middleware ordering: UseAuthentication → UseAuthorization in Program.cs
- Create `ClaimsPrincipalExtensions`: GetUserId(), GetUserTier(), GetUserEmail() — extract from JWT claims
- Create global exception middleware: catches unhandled exceptions, returns 500 (no stack trace in prod), logs full details via Serilog
- Add Swagger Bearer auth configuration so the Authorize button appears in Swagger UI
- Protected test endpoint: `GET /test-auth` behind `[Authorize]` — returns user info from claims
- **Out of scope:** Role-based authorization, policy-based authorization

## Acceptance Criteria
1. Endpoints with `[Authorize]` return 401 without a valid JWT
2. Endpoints with `[Authorize]` return 200 with a valid JWT
3. `GetUserId()` returns correct GUID from JWT sub claim
4. `GetUserTier()` returns tier claim set during login
5. Global exception middleware catches unhandled exceptions and returns 500
6. Swagger Authorize button accepts JWT and applies to all requests

## Definition of Done
- [ ] Auth middleware in correct order in Program.cs
- [ ] ClaimsPrincipalExtensions working for ID, email, tier
- [ ] Test endpoint behind [Authorize] returns user info
- [ ] Unauthorized requests return 401 with WWW-Authenticate header
- [ ] Global exception middleware registered
- [ ] Swagger Bearer auth configured
- [ ] Ready for all protected API endpoints
