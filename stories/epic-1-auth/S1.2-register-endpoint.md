# S1.2: Email/Password Registration Endpoint

**Epic:** 1 — Authentication & User Management
**Depends-on:** S1.1
**Priority:** HIGH

## Context
Create the registration endpoint. Accepts email, password, mobile number, and community contribution consent. Uses Identity's UserManager to create the user. The endpoint does NOT issue tokens — the user logs in separately via S1.3.

## Scope
- `POST /auth/register` endpoint accepting email, password, mobile, and consent flag
- Request validation: email format, password min 8 chars, Singapore mobile format (8 or 9, 8 digits)
- Email uniqueness check — returns 409 if email already exists
- Account created immediately (no email verification for MVP)
- Password stored as PBKDF2 hash via Identity
- Serilog logging on registration events
- **Out of scope:** Token issuance, email verification, rate limiting

## Acceptance Criteria
1. Valid registration creates a user, returns 200 with success message (no tokens)
2. Existing email returns 409 with `EMAIL_EXISTS` error
3. Password < 8 chars returns 400 validation error
4. Invalid email format returns 400
5. Password stored as hash in DB (verify by querying users table)
6. CommunityContributionConsent stored correctly (true/false)
