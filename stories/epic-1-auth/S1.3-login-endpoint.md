# S1.3: Email/Password Login + JWT Issuance

**Epic:** 1 — Authentication & User Management
**Depends-on:** S1.1
**Priority:** HIGH

## Context
Create the login endpoint. Validates credentials against Identity, issues a short-lived JWT access token (15 min) and a rotating refresh token (30 days). The JWT contains user ID, email, and tier claims. The refresh token hash is stored in the DB for rotation. All authenticated API calls use the JWT.

## Scope
- `POST /auth/login` endpoint accepting email and password
- Credential validation via UserManager — generic "invalid credentials" error for both wrong email and wrong password (no user enumeration)
- JwtService: generates JWT with sub, email, tier claims; signed with HS256; 15-min expiry
- TokenService: generates cryptographically random refresh token, stores SHA256 hash in DB with 30-day expiry
- JWT Bearer authentication middleware configured in Program.cs
- Return: access token, refresh token, user profile
- **Out of scope:** Refresh token rotation (S1.5), Google sign-in (S1.4)

## Acceptance Criteria
1. Valid credentials → 200 with JWT + refresh token + user profile
2. Wrong password → 401 `INVALID_CREDENTIALS`
3. Non-existent email → 401 `INVALID_CREDENTIALS` (same error — no user enumeration)
4. JWT decodes to reveal sub, email, tier claims
5. JWT expires after 15 minutes (expired token → 401)
6. Refresh token stored as SHA256 hash (not plaintext) in DB
7. Multiple logins create multiple refresh tokens (all valid)
