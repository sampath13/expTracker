# S1.4: Google Sign-in Integration (Backend)

**Epic:** 1 — Authentication & User Management
**Depends-on:** S1.1, S1.3
**Priority:** HIGH

## Context
Add Google as an external authentication provider. The mobile app sends a Google ID token obtained via the Google Sign-In SDK; the backend validates it with Google's token verification service and creates or links a local account. JWT + refresh token are issued just like email login. First-time Google users are prompted for a mobile number.

## Scope
- `POST /auth/google` endpoint accepting Google ID token and platform (android/ios)
- Google ID token validation against Google's public keys (using Google.Apis.Auth library)
- Platform-specific audience validation (Android client ID vs iOS client ID)
- Find user by Google ID → return tokens
- If email already registered (email/password user): link Google ID to existing account
- If new user: create account, return `isNewUser: true` and `requiresMobile: true`
- Google-only users have null password hash (cannot log in via email)
- `GoogleAuth:AllowTestTokens` config for development without real Google project
- **Out of scope:** Apple Sign-in, multi-provider account linking UI

## Acceptance Criteria
1. Valid Google ID token → 200 with JWT + refresh token + user profile
2. First-time Google login creates new user with GoogleId set
3. Returning Google login finds existing user by GoogleId
4. New user response includes `isNewUser: true` and `requiresMobile: true`
5. Existing email/password user links Google ID (account merging)
6. Invalid/expired Google token → 401
7. Google user password hash is NULL

## Definition of Done
