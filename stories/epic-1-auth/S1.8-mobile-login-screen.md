# S1.8: Mobile — Login Screen

**Epic:** 1 — Authentication & User Management
**Depends-on:** S0.1, S0.2, S0.11, S1.3, S1.4
**Priority:** HIGH

## Context
Build the login screen. Users can sign in with email/password or Google Sign-in. On success, tokens are stored securely (Android Keystore) and the app navigates to the main screen. New Google users who haven't provided a mobile number are prompted to do so.

## Scope
- Login screen with email and password fields, "Log In" button
- "Sign in with Google" button using Google Sign-In SDK
- On success: store JWT + refresh token in secure storage, set auth state in Zustand via `authStore`, navigate to main app
- On Google success with `requiresMobile: true`: navigate to MobileEntryScreen
- Loading spinner during API calls; inline error display for invalid credentials
- Error handling for network failures (no connectivity)
- Wire to `authService.login()` and `authService.googleLogin()` from S0.11 (API client module)
- **Out of scope:** API client module (see S0.11), social logins beyond Google, biometric auth

## Acceptance Criteria
1. Email + password login works: valid → main app; invalid → error message
2. Google sign-in: returns tokens, navigates to main app
3. New Google user without mobile → MobileEntryScreen shown
4. Tokens stored in Android Keystore (secure, survives app restart)
5. Network error shows "Connection error. Please try again."
6. Both login flows call S0.11's authService methods (not direct HTTP calls)

## Definition of Done
- [ ] LoginScreen with email/password form + Google button
- [ ] MobileEntryScreen for first-time Google users
- [ ] Tokens securely stored in Keystore
- [ ] Zustand auth slice updated (login, loginWithGoogle actions)
- [ ] Ready for S1.10 (token management), S1.11 (navigation guard)
