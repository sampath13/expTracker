# S0.4: react-native-permissions Foundation

**Epic:** 0 — Project Scaffold & Cross-Cutting Concerns
**Depends-on:** S0.1
**Priority:** HIGH

## Context
Create a permission abstraction layer using `react-native-permissions`. The camera is the only permission needed for MVP — images are stored in the app's private cache directory, which requires no storage permission on Android 10+. The abstraction handles the full lifecycle: check current state, request if denied, guide user to system settings if permanently blocked.

## Scope
- Install and configure `react-native-permissions`
- Declare CAMERA permission in AndroidManifest (no storage permissions)
- Create a generic `usePermission` hook (check, request, openSettings)
- Create a `useCameraPermission` hook wrapping the generic hook for camera
- Create a `PermissionGate` component that renders children only if permission is granted
- Add a temporary dev-test button on the Home placeholder to trigger permission flow
- **Out of scope:** iOS permissions, gallery photo pick, background permissions

## Acceptance Criteria
1. `useCameraPermission` correctly reports: granted, denied, blocked, unavailable
2. First launch: requesting camera shows Android native permission dialog
3. If permanently blocked: user is guided to system settings
4. Permission state persists across app restarts
5. AndroidManifest does NOT contain READ_EXTERNAL_STORAGE or similar
