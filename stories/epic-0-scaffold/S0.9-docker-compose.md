# S0.9: Docker Compose Dev Environment

**Epic:** 0 — Project Scaffold & Cross-Cutting Concerns
**Depends-on:** S0.6, S0.7, S0.8
**Priority:** HIGH

## Context
Wire all services together with Docker Compose under the `docker/` directory so the full stack can be started with a single command. PostgreSQL, .NET API, Python OCR service, and S3Ninja all run locally. Zero dependency on AWS or external services for development.

## Scope
- `docker/docker-compose.yml` with four services: PostgreSQL 16, S3Ninja (S3 emulation), .NET API, Python OCR
- Each service has health checks and proper `depends_on` ordering
- `docker/postgres/init.sql` creates both databases on first start
- S3Ninja configured with bucket `receipt-images` and access credentials matching dev config
- Dockerfiles for .NET API (`apps/api/Dockerfile` — multi-stage) and OCR service (`apps/ocr-service/Dockerfile` — with PaddleOCR model pre-downloaded in build layer)
- `.env` and `.env.example` for configuration values (at repo root)
- `.dockerignore` files to minimize build context (in each app directory)
- `docker compose up` starts all services; `docker compose down` tears them down cleanly
- Commands run with `-f docker/docker-compose.yml` or working directory set to `docker/`
- **Out of scope:** Production deployment, CI/CD pipeline

## Acceptance Criteria
1. `docker compose -f docker/docker-compose.yml up` starts all four services without errors
2. PostgreSQL accepts connections on port 5432; both databases created
3. S3Ninja runs on port 9444; `receipt-images` bucket exists
4. .NET API runs on port 5000; Swagger accessible
5. OCR service runs on port 8000; model loaded
6. S3 file upload/download works against S3Ninja via AWS CLI or SDK
7. `docker compose up` is idempotent on second run
