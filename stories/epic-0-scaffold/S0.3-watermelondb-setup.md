# S0.3: WatermelonDB Setup

**Epic:** 0 — Project Scaffold & Cross-Cutting Concerns
**Depends-on:** S0.1
**Priority:** HIGH

## Context
Set up WatermelonDB as the on-device SQLite database for offline expense history. Define the local schema (users, bills, bill_items) and verify tables create on first launch. The sync adapter that connects to the cloud is a separate story (S4.5) — this story only establishes the local database foundation.

## Scope
- Install WatermelonDB and its SQLite adapter
- Define model classes for User, Bill, and BillItem matching the cloud schema
- Define the local database schema: table columns, foreign keys
- Create a DatabaseProvider that initializes the database singleton on app start
- Verify tables exist via a test create/query/delete of a dummy record
- Provide a `resetDatabase()` helper for development
- **Out of scope:** Sync adapter, actual data flow from cloud to local

## Acceptance Criteria
1. App launches and WatermelonDB initializes without errors
2. Tables `users`, `bills`, `bill_items` exist in local SQLite
3. A dummy record can be created, saved, and queried back
4. `resetDatabase()` drops and recreates tables cleanly
5. No native build errors related to the SQLite adapter

## Definition of Done
- [ ] WatermelonDB installed with working native adapter (MIT license confirmed)
- [ ] Schema validates — no missing table errors on launch
- [ ] Model classes created for User, Bill, BillItem
- [ ] DatabaseProvider exports singleton database
- [ ] Dummy write/read test passes
- [ ] Ready for S4.5 (sync adapter)
