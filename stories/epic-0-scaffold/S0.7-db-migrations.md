# S0.7: Database Migrations & EF Core Models

**Epic:** 0 — Project Scaffold & Cross-Cutting Concerns
**Depends-on:** S0.6
**Priority:** HIGH

## Context
Create Entity Framework Core models and generate initial migrations for both databases: Personal Bills DB and Comparison Pool DB. Seed the Comparison Pool with the 10 product categories and 6 retail chains. This defines the canonical data schema that WatermelonDB mirrors and all API stories write to.

## Scope
- EF Core entity models for all tables in both DBs (per architecture.md sections 5.1 and 5.2)
- Two `DbContext` classes: `PersonalBillsDbContext` (users, refresh tokens, bills, bill items, retailers, consent audit) and `ComparisonPoolDbContext` (categories, products, retail chains, outlets, prices)
- Fluent API configurations: unique indexes, foreign keys with cascade/restrict behavior, composite indexes for price lookups, JSONB columns for arrays
- Initial migrations generated and verified for both contexts
- Seed data: 10 categories with keyword prefixes, 6 retail chains
- Idempotent seed — safe to run multiple times
- Health check updated to report PostgreSQL connectivity
- **Out of scope:** Identity migrations (S1.1 adds those), manual seed data for products/prices (S6.3)

## Acceptance Criteria
1. Both DbContexts compile with all entity models and relationships
2. Migrations apply successfully against a local PostgreSQL instance
3. Category seed data populates 10 categories on first run
4. Retail chains seed populates 6 chains
5. Re-running migrations/seed does not create duplicates
6. Health check reports DB status accurately
