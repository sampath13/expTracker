# S0.8: Python OCR Service Scaffold

**Epic:** 0 — Project Scaffold & Cross-Cutting Concerns
**Depends-on:** None
**Priority:** HIGH

## Context
Create the Python FastAPI OCR microservice in `apps/ocr-service/`. Set up PaddleOCR with English and Chinese models, OpenCV for image processing, and RapidFuzz for fuzzy matching. Follow the src-layout: business logic lives in `src/ocr_service/`, route handlers in `api/`, models in `schemas/`. Verify that a sample receipt image can be processed end-to-end (raw text extraction only — no structured parsing yet).

## Scope
- FastAPI project in `apps/ocr-service/` with virtual environment and `requirements.txt`
- src-layout: `src/ocr_service/` package with `main.py`, `config.py`, `api/` (routers), `schemas/` (Pydantic models), `services/` (preprocessing, ocr, parsing, matching stubs), `core/` (exceptions)
- PaddleOCR English model loaded at startup; Chinese model loaded if available (graceful fallback)
- `GET /health` endpoint returning model load status
- `POST /ocr/test` endpoint accepting a receipt image, running raw PaddleOCR, returning text blocks with confidence scores
- S3 client configured (talks to S3Ninja in dev) — not wired yet
- Sample receipt test fixture added
- `tests/` directory with `conftest.py`, `unit/`, `integration/`, `fixtures/`
- **Out of scope:** Preprocessing pipeline, receipt field parsing, product matching, REST endpoints beyond test/health

## Acceptance Criteria
1. `python -m uvicorn src.ocr_service.main:app` starts FastAPI on port 8000
2. `GET /health` returns 200 with `model_loaded: true`
3. `POST /ocr/test` with a sample receipt returns text blocks with text, confidence, and bounding boxes
4. PaddleOCR model loads at startup via lifespan hook (not on first request)
5. Subsequent `/ocr/test` calls return in < 3 seconds for a standard receipt
6. `requirements.txt` produces identical install on a clean machine
