# S0.2: Zustand Store Skeleton

**Epic:** 0 — Project Scaffold & Cross-Cutting Concerns
**Depends-on:** S0.1
**Priority:** HIGH

## Context
Set up Zustand as the state management library. Define four store slices (auth, scan, expenses, compare) with their initial state shapes and action signatures. No business logic yet — only the shape of each slice so feature stories can wire into them. Zustand is provider-free, meaning no wrapping components needed in the app tree.

## Scope
- Install Zustand
- Create four store files: `authStore`, `scanStore`, `expensesStore`, `compareStore`
- Each store has initial state and stubbed action functions (named, typed, no-op bodies)
- Central export from `src/store/index.js`
- **Out of scope:** Any real implementation of store actions

### State Shape Definitions

**authStore** — Authentication state slice
```typescript
{
  isAuthenticated: false,
  isLoading: true,
  user: null,                          // { id, email, mobile, tier, googleLinked }
  tokens: {
    accessToken: null,                 // JWT string
    refreshToken: null                 // opaque refresh token string
  },
  error: null                          // string | null
}
```
Actions: `setTokens`, `setUser`, `setLoading`, `clearAuth`, `initialize` (all no-op stubs)

**scanStore** — Receipt capture state slice
```typescript
{
  capturedImagePath: null,             // local file:// URI
  uploadProgress: 0,                   // 0-100
  uploadStatus: 'idle',                // 'idle' | 'uploading' | 'success' | 'error'
  objectKey: null,                     // S3 key for uploaded receipt
  ocrResult: null,                     // raw { retailer, date, items[] } from OCR
  isManualEntry: false,
  error: null
}
```
Actions: `captureImage`, `uploadImage`, `setOcrResult`, `setManualEntry`, `resetScan` (all no-op stubs)

**expensesStore** — Expense history state slice
```typescript
{
  bills: [],                           // WatermelonDB bill records
  cursor: null,                        // pagination cursor for GET /bills
  hasMore: true,
  isLoading: false,
  syncStatus: 'idle',                  // 'idle' | 'syncing' | 'success' | 'error'
  currentBill: null,                   // bill detail being viewed
  error: null
}
```
Actions: `fetchBills`, `appendBills`, `setCurrentBill`, `upsertBill`, `removeBill`, `syncBills` (all no-op stubs)

**compareStore** — Price comparison state slice
```typescript
{
  searchQuery: '',
  searchResults: [],                   // autocomplete product list
  currentComparison: null,             // single-item comparison result
  basketComparison: null,              // multi-item aggregate result
  isLoading: false,
  error: null
}
```
Actions: `searchProducts`, `compareItem`, `compareBasket`, `clearComparison` (all no-op stubs)

## Acceptance Criteria
1. All four stores importable and callable without errors
2. Each store initializes with the exact default state shape defined above
3. No provider or wrapper needed in component tree
4. All action function signatures defined (parameters and return types per above)
5. `resetScan` clears all scan state; `clearAuth` resets auth state; `clearComparison` resets compare state

## Definition of Done
- [ ] Four store files exist with correct exports
- [ ] Zustand installed with no version conflicts
- [ ] Each store initialises with default state exactly matching the shapes defined in this story
- [ ] No runtime errors on app launch
- [ ] Ready for S1.10 (auth state), S2.4 (upload state), S4.6 (expense state), S5.4 (compare state)
