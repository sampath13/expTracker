# S0.5: Camera Capture & File I/O

**Epic:** 0 — Project Scaffold & Cross-Cutting Concerns
**Depends-on:** S0.4
**Priority:** HIGH

## Context
Integrate the camera (react-native-vision-camera) and file system (react-native-fs) libraries. The camera captures a receipt photo; the image is saved to the app's private cache directory (no storage permission needed). After upload to the backend, the local file is deleted. This story also includes on-device blur detection to prevent uploading poor-quality images.

## Scope
- Install react-native-vision-camera v4+ and react-native-fs
- Create a `CameraView` component: full-screen preview, capture button, flash toggle
- Photo saved to app cache: `{cacheDir}/captures/{timestamp}.jpg`
- Create image utility functions: capture, delete, directory management
- On-device blur detection via Laplacian variance (native Android module or JS approximation)
- Quality check returns `{ isValid, issues }` — blurry images prompt retake
- Temporary dev integration: "Test Camera" button on Home screen
- **Out of scope:** Upload flow, gallery pick, multi-image stitching

## Acceptance Criteria
1. CameraView renders live preview and captures a photo
2. Photo saved to app cache directory — verified file exists at path
3. No storage permission required — verify on Android 13+ emulator
4. Blur detection: blurry image triggers retake prompt; sharp image passes
5. Flash toggle cycles through auto/on/off
6. Local image delete removes file completely
