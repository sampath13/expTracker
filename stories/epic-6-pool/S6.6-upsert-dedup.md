# S6.6: UPSERT Deduplication Logic

**Epic:** 6 — Crowdsourced Pool & Seed Data
**Depends-on:** S4.3
**Priority:** MEDIUM

## Context
Define and implement the deduplication logic for the Comparison Pool prices table. When multiple users contribute the same price for the same product at the same chain in the same month, the receipt_count increments rather than creating duplicate rows. When the price differs (e.g., promotional pricing), a new row is created. This keeps the pool clean and the trust indicators accurate.

## Scope
- UPSERT key: (product_id, chain_id, outlet_id, price, observed_month)
- If an existing row matches all five fields: increment `receipt_count`, update `last_observed` to current date
- If any field differs (e.g., different price): insert a new row
- Outlet-level granularity: if same product at same chain but different outlet, separate row
- This logic applies to both user_scan and manual_seed sources (though manual_seed entries should already be unique)
- **Out of scope:** Price normalization across units (e.g., "$3.25/600g" vs "$5.42/kg"), outlier detection

## Acceptance Criteria
1. Same product + chain + price + month → receipt_count incremented (no duplicate)
2. Different price for same product + chain + month → new row inserted
3. Different outlet for same product + chain + price → new row
4. Outlet_id NULL and outlet_id NOT NULL for same product + chain + price → separate rows

## Definition of Done
- [ ] UPSERT logic implementation in ComparisonContributionService
- [ ] Deduplication by (product, chain, outlet, price, month) composite key
- [ ] receipt_count correctly incremented on duplicate
- [ ] New rows created when any key field differs
- [ ] Ready for clean, trustworthy comparison data
