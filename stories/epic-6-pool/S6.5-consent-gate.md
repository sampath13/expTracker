# S6.5: Consent Gate Enforcement

**Epic:** 6 — Crowdsourced Pool & Seed Data
**Depends-on:** S1.7, S4.3
**Priority:** HIGH

## Context
Enforce the community contribution consent flag at the data pipeline level. When a user has `CommunityContributionConsent = false`, their confirmed bill items are saved to their personal DB but NOT written to the Comparison Pool. This is the technical enforcement of the PDPA consent promise.

## Scope
- In `POST /bills/confirm` (S4.3): check user's consent flag before calling comparison contribution service
- If consent is false: skip pool write entirely — bill saved to personal DB only
- If consent is changed to false after past contributions: existing contributions remain in pool (not retroactively removed — policy decision); new confirmations are not contributed
- Consent check happens per-confirm, not cached — respects recent consent changes
- Log consent-skip events: "Pool contribution skipped for user {id} — consent not given"
- **Out of scope:** Retroactive removal of past contributions, granular per-bill consent override

## Acceptance Criteria
1. User with consent ON → bill items flow to pool
2. User with consent OFF → bill items saved to personal DB only, pool skipped
3. User toggles from ON to OFF → new bills not contributed; past contributions remain
4. User toggles from OFF to ON → next bill contributes normally
5. Consent state read fresh on each confirm (not cached from login)

## Definition of Done
- [ ] Consent check in POST /bills/confirm flow
- [ ] Pool write skipped when consent is false
- [ ] Existing contributions not retroactively removed
- [ ] Consent change effective immediately (next confirm)
- [ ] Logging for consent-skip events
- [ ] Ready for GDPR/PDPA consent compliance
